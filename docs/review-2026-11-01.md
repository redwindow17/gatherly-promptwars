## Changes and reasons

- **Smaller browser validation:** switched the shared schemas and provider envelope to
  Zod Mini while retaining strict objects, field limits, date checks, duplicate-ID
  rejection, and English validation messages. Terser handles production compression;
  the extra build work reduces the JavaScript users download.
- **Less synchronous save work:** only changed budget amounts trigger a save. Storage
  skips identical writes and remembers the exact previously validated payload. It
  still reads the current storage value before every save, so an externally changed
  or damaged payload must pass validation/recovery before replacement. Mutable plan
  objects are never trusted through a cache.
- **Reusable date formatters:** bounded caches avoid repeated Intl construction.
  Date-only labels use UTC internally so changing the device timezone cannot move a
  displayed calendar day. Event planning still uses the host's selected IANA zone.
- **Clear component boundaries:** sidebar, welcome content, and seven workspace views
  have dedicated modules; task rendering and typed view props are shared. The existing
  stylesheet and product layout are preserved. TypeScript now rejects unused code.
- **Correct HTTP failures:** malformed client UTF-8 returns 400, malformed provider
  bytes remain a 502, and rejected body streams are cancelled and unlocked.
- **Accessible correction text:** invalid budget fields explicitly reference their
  explanation through `aria-describedby`.
- **Automatic verification:** a GitHub workflow runs formatting, tests, typechecked
  production build, bundle budgets, and vulnerability checks. Action versions are
  pinned to verified commit hashes, permissions are read-only, and there is no deploy step.

## Measured evidence

Baseline: repository commit `9368048`, using the same installed application dependencies
on Node 24.12.0. Build measurements sum the browser JavaScript files; this is not a
Lighthouse or network-latency measurement.

| Measurement                      |     Before |     After |
| -------------------------------- | ---------: | --------: |
| Browser JavaScript, gzip         |   117.4 kB |   99.6 kB |
| Browser JavaScript, uncompressed |   389.2 kB |  318.4 kB |
| CSS, gzip                        |    12.2 kB |   12.2 kB |
| Automated tests                  |        106 |       116 |
| Worker bundle, gzip              | 127.04 KiB | 20.99 KiB |

The compressed JavaScript reduction is approximately 15%. `npm run bundle:check`
enforces 100,000 bytes for the sum of gzipped JavaScript and 20,000 bytes for CSS.
The Worker gzip size fell about 83%, based on Wrangler's baseline upload report and
the current successful deployment dry-run. No deployment was performed.

The offline storage benchmark uses 12 synthetic plans, a 663,539-character payload,
ten warmups, and forty timed samples. A representative sequential before/after run
measured median saves at 13.070 ms versus 2.952 ms and loads at 6.945 ms versus 2.761 ms.
Timings vary with machine load; they cover validation and serialization using a Map
storage adapter, not browser disk I/O or a live device. Reproduce the current measurement
with `npm run benchmark:storage`; compare the baseline by running the same script
against the source at `9368048` in a separate checkout.

## Regression coverage

New failing tests reproduced the unchanged-budget save warning, redundant unchanged
storage write, missing accessible error association, incorrect malformed-body status,
and uncancelled stream. The formatter-cache review also reproduced a date shift after
a device timezone change and fixed it before release. A UI integration test edits a
budget, completes a task and vendor question, navigates between views, then remounts
the app and verifies the saved results. Existing corrupt-data recovery, full-library,
provider timeout, money/date, calendar, and media-range tests remain in the suite.

## Scope and limits

This is a repository-only improvement. It does not configure a Gemini key, perform a
live generation, change the public deployment, publish a social post, or submit a new
challenge attempt. Provider tests use controlled synthetic responses. Rendered UI
tests run in jsdom; a fresh real-browser/device performance audit was not performed.
The published starter demo remains the earlier deployment.

The build reports two existing non-fatal annotation warnings in Zod's dependency
source. They do not prevent the production build or the enforced size check.
